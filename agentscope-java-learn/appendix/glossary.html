附录 A · 术语表：中英对照 + 一句话直觉

读官方文档最烦的不是英文，是一个概念有五个名字：代码里叫 ToolUseBlock，文档里叫 tool call，界面上叫「工具调用」，中文教程里又叫「函数调用」。这张表按主题把 2.0.4 里真正会遇到的术语各给一句话， 每行都标了第一次讲它的章节——忘了就回去看那一章，别在这里硬背。

怎么用这张表

  • 先看「一句话直觉」那一列。名字只是索引，直觉才是能用的东西
  • 标 ★ 的是必须能脱口而出的：说不清它们，后面的章节会一直卡
  • 「章」这一列是第一次系统讲它的地方；附录只负责提醒，不负责讲透
  • 表里出现的类名都可以在源码里搜到，包路径统一是 io.agentscope.core.*，Harness 的在 io.agentscope.harness.agent.*
三对最容易混的概念，先在这里分清

State vs Memory：AgentState 是「一份会话的全部可存内容」，Memory 只是其中「进上下文的那串消息」。Hook vs Middleware：Hook 是切点回调（到点叫你）， Middleware 是包裹层（能改写这一段怎么做）。Event vs HookEvent：AgentEvent 是给外部消费者的事件流，HookEvent 是给框架内部 Hook 的切点对象，两套类型不通。

Agent 与运行时

术语中文一句话直觉章
Agent ★ 智能体接口 只承诺四件事：能 call、能被 observe、有旧版 stream、能发事件；streamEvents 不在这个接口上 10
AgentBase 智能体基类 所有 agent 的共同底座：生命周期、Hook 分发、错误兜底、优雅停机登记 10
ReActAgent ★ ReAct 引擎 唯一的内置循环实现：「推理 → 调工具 → 再推理」，全站 18 章的每个能力最后都落到它 02
HarnessAgent ★ Harness 外壳 不是 ReActAgent 的子类：它 implements Agent, AutoCloseable，内部持有一个 delegate 10
delegate 被委托者 Harness 内部真正在跑循环的那个 ReActAgent 实例；Harness 只做转发和加装 10
RuntimeContext ★ 运行时上下文 一次调用的「我是谁、在哪个会话」：userId + sessionId，每次调用都可以不同 02
session 会话 就是 (userId, sessionId) 这对坐标；换坐标 = 换一份记忆，换一份权限规则 07
AgentRun 一次运行 描述某一次调用处在哪个阶段（排队 / 运行 / 完成 / 失败），不是「会话」 10
RunControl 运行控制 决定这次调用是排队、开跑还是被取消；中断能否生效取决于它此刻的状态 10
interrupt() 中断 让正在跑的循环在下一个检查点停下，结果消息的 reason 是 INTERRUPTED 10
graceful shutdown 优雅停机 JVM 要关时，先把在跑的请求收尾并落盘，而不是直接掐掉 10

消息与内容块

术语中文一句话直觉章
Msg ★ 消息 对话的最小单位：role + 内容块列表 + metadata；getTextContent() 在没有文本时返回空串而不是 null 04
MsgRole 消息角色 只有四个：USER / ASSISTANT / SYSTEM / TOOL 04
ContentBlock ★ 内容块 一条消息里可以同时有文本、思考、工具调用、图片——不是一个消息一种类型 04
TextBlock 文本块 你看到的「回答正文」 04
ThinkingBlock 思考块 推理模型的思维链；存进记忆，但不会再发给模型 04
ToolUseBlock ★ 工具调用块 模型说「我要调这个工具」：id / name / input / state，HITL 全靠 id 对齐 04
ToolResultBlock 工具结果块 工具执行后的结果：内容块 + ToolResultState + 关联的调用 id 04
DataBlock 数据块 图片 / 音频 / 视频 / 文件的统一容器（旧的 ImageBlock 等还在，但新代码用它） 04
HintBlock 提示块 中间件或 RAG 插进来的「背景提示」，不算对话历史，也不会污染 assistant 正文 04
ToolCallState 调用状态 PENDING → ASKING → ALLOWED → SUBMITTED → FINISHED，ASKING 就是「等你批」 08
ToolResultState 结果状态 SUCCESS / ERROR / INTERRUPTED / DENIED / RUNNING 04
GenerateReason ★ 结束原因 这一轮为什么停下来，12 个枚举值；判断是否暂停只能看它 04
metadata 元数据 挂在消息上的字典；HITL 的 ConfirmResult 就藏在 Msg.METADATA_CONFIRM_RESULTS 这个 key 下 08

MsgRole 只有 4 个值：MsgRole.java:35；GenerateReason：GenerateReason.java:36；ToolCallState：ToolCallState.java:20；ToolResultState：ToolResultState.java:20；思考块不回传：AbstractBaseFormatter.java:121

GenerateReason 的 12 个值，一次看全
值含义你该做什么
MODEL_STOP模型正常说完结束，读文本
TOOL_CALLS模型给了工具调用，框架继续跑通常不会作为最终结果出现
STRUCTURED_OUTPUT结构化输出完成从 metadata 取结构化数据
TOOL_SUSPENDED工具主动挂起，等外部结果按 ExternalExecutionResultEvent 的约定回填
REASONING_STOP_REQUESTEDHook 在推理阶段叫停看自己的 Hook 逻辑
ACTING_STOP_REQUESTEDHook 在行动阶段叫停看自己的 Hook 逻辑
PERMISSION_ASKING权限引擎要你确认收集 ASKING 工具，回传 ConfirmResult
MIDDLEWARE_STOP_REQUESTED中间件请求暂停无参数再调一次 call() 继续
ALL_TOOLS_DENIED这轮工具全被拒，且 Hook 叫停换策略或换提示词
INTERRUPTED被 interrupt() 打断决定重试还是放弃
MAX_ITERATIONS撞到 maxIters框架会多做一次摘要调用；调大上限或简化任务
TOOL_RETURN_DIRECT工具结果直接当最终答案不用再等模型说话

状态与记忆

术语中文一句话直觉章
AgentState ★ 智能体状态 一份会话的全部可持久化内容：消息上下文、权限上下文、工具上下文、任务列表…… 07
AgentStateStore ★ 状态存储 按 (userId, sessionId, key) 读写；实现可换文件 / 内存 / Redis / MySQL 07
State 可存状态 能被 store 序列化的标记接口；不是所有对象都能往里塞 07
JsonFileAgentStateStore 文件状态存储 落盘到 <root>/<userId>/<sessionId>/，一个 JSON + 一个 JSONL 07

事件、Hook 与中间件

术语中文一句话直觉章
AgentEvent ★ 智能体事件 事件流里的最小单位，每个都带 replyId；2.0.4 里有 31 种类型 04
replyId 回复 id 一次调用内所有事件的关联键；并发调用时靠它分组 04
start / delta / end 三段式 文本、思考、数据、工具调用、工具结果都是「开始 → 增量 → 结束」三件套 04
AgentResultEvent 结果事件 生命周期正常结束时发，携带最终 Msg；暂停也算正常结束 11
AgentEndEvent 结束事件 doFinally 里必发，无论是成功、失败还是取消 11
Hook ★ 钩子 在固定切点被回调；能读能改事件，也能 stopAgent() 09
HookEvent 钩子事件 Hook 收到的对象：PreCall / PostReasoning / PreActing…… 与 AgentEvent 不是一套 09
MiddlewareBase 中间件 包住「模型调用 / 推理 / 行动」三段，能替换这一段怎么做，而不只是旁观 09
MiddlewareChain 中间件链 多个中间件的执行顺序；顺序错了，后面的看不到前面的改动 09
stopAgent() 主动叫停 Hook 在某个切点结束本轮，对应 *_STOP_REQUESTED 系列 reason 09
