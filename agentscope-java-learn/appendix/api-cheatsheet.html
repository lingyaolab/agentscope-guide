附录 C · API 速查：Builder 方法按能力分组

ReActAgent.Builder 有 43 个 public Builder xxx(...)， HarnessAgent.Builder 有 97 个。这份表把两边合起来按能力分组： 共有的 28 个名字先看一次，剩下的再分成「core 独有」和「Harness 专有的七组」。 每个方法一句话，标了默认值和容易踩的点，不重复章节里的讲解。

怎么用这一页

  • 先看共有组：28 个名字覆盖了 90% 的日常配置，学会这些就能写出第 11 章那种工程
  • 所有方法都返回 this，可以链式调用；校验大多发生在 build() 或首次调用，不是设置的那一刻
  • 表里的「默认」只写框架自己的默认值；你写了就以你为准
  • 两个数字可以自己数：在类文件里搜 public Builder。数出来 ReActAgent 43、HarnessAgent 97（含重载）
一个数字对不上的地方：43 + 66 ≠ 97 的直觉

因为重载算了多次。按「名字」去重后：共有 28 个名字（31 个方法签名）， core 独有 12 个，Harness 独有 58 个。28 + 58 = 86 个名字， 再加上 model、fallbackModel、workspace、filesystem 等重载，正好凑成 97。

2. 生产级 core：持久化 + 超时 + 权限

import io.agentscope.core.ReActAgent;
import io.agentscope.core.model.ExecutionConfig;
import io.agentscope.core.permission.PermissionContextState;
import io.agentscope.core.permission.PermissionMode;
import io.agentscope.core.state.AgentStateStore;
import io.agentscope.core.state.JsonFileAgentStateStore;

import java.nio.file.Path;
import java.time.Duration;

AgentStateStore store = new JsonFileAgentStateStore(
        Path.of(System.getProperty("user.home"), ".agentscope", "state", "ops"));

ReActAgent agent = ReActAgent.builder()
        .name("ops-assistant")
        .model("dashscope:qwen-plus")
        .fallbackModel("openai:gpt-5.5")
        .maxRetries(2)                                  // 含首次：2 = 1 次首发 + 1 次重试
        .modelExecutionConfig(ExecutionConfig.builder()
                .timeout(Duration.ofSeconds(60))
                .build())
        .toolExecutionConfig(ExecutionConfig.builder()
                .timeout(Duration.ofSeconds(30))
                .build())
        .permissionContext(PermissionContextState.builder()
                .mode(PermissionMode.DEFAULT)
                .build())
        .stateStore(store)
        .build();
两个重试旋钮别写混

maxRetries(2) 与 ExecutionConfig.maxAttempts(2) 是同一个计数口径： 都含首次。2 表示「1 次首发 + 1 次重试」，不是「首发 1 次再重试 2 次」。

3. Harness 全功能骨架：工作区 + 压缩 + 子 agent

import io.agentscope.harness.agent.HarnessAgent;
import io.agentscope.harness.agent.memory.compaction.CompactionConfig;

import java.nio.file.Paths;

HarnessAgent agent = HarnessAgent.builder()
        .name("coding-agent")
        .agentId("coding-agent")                       // 状态目录与文件系统命名空间
        .model("dashscope:qwen-plus")
        .workspace(Paths.get(".agentscope/workspace"))
        .compaction(CompactionConfig.builder()
                .triggerMessages(30)
                .keepMessages(10)
                .build())
        .enableTaskList()                              // 长任务让它自己拆 TODO
        .enablePlanMode()                              // 先出方案，再动手
        .disableWebTools()                             // 内网/离线部署
        .subagentFactory("reviewer", agentName -> HarnessAgent.builder()
                .name(agentName)
                .model("dashscope:qwen-plus")
                .sysPrompt("你是代码审查员，只报告真正的问题。")
                .build())
        .build();

subagentFactory 的 lambda 参数是子 agent 自己的名字，不是任务文本： 框架在物化子 agent 时用这个名字调用工厂，任务则是之后通过 call 传进去的。返回值必须是 Agent；HarnessAgent 本身实现了 Agent，所以可以直接返回。

4. 只读分析：EXPLORE 不是「先问一下」

import io.agentscope.core.ReActAgent;
import io.agentscope.core.permission.PermissionContextState;
import io.agentscope.core.permission.PermissionMode;

ReActAgent agent = ReActAgent.builder()
        .name("explorer")
        .model("dashscope:qwen-plus")
        // EXPLORE：只读工具放行，其余一律 DENY —— 不是挂起等人，是根本不执行
        .permissionContext(PermissionContextState.builder()
                .mode(PermissionMode.EXPLORE)
                .build())
        .build();

判断依据是工具的 isReadOnly()。注意内置的 view_text_file / list_directory 等并没有标 readOnly = true，EXPLORE 下会被拒；自己写的工具要加 @Tool(readOnly = true)。所以「我只想让 agent 看代码」不能只靠 EXPLORE，还要补注解。

5. 无人值守：不挂起、全拒就停

五种「以为有、其实没有」的写法

这些写法在旧版本、别的框架或官方 Python 示例里都出现过，在 2.0.4 的 Java 里会对不上。编译器报 「找不到符号」时先来这里扫一眼。

不存在的写法为什么改成
.modelOptions(...)生成参数不在模型 id 上，也没有这个方法.generateOptions(GenerateOptions.builder()...build())
toolUseBlock.withInput(...)内容块是不可变的，没有 withXxxToolUseBlock.builder().id(原 id).name(原名).input(新参数).build()，id 必须保留
new RedisAgentStateStore(pool)没有这个构造器RedisAgentStateStore.builder().jedisClient(unifiedJedis).build()，也支持 Lettuce / Redisson 适配
agent.getAgentName()Agent 接口没有这个名字ReActAgent#getName()；别和 EventSource#getAgentName() 混
ExecutionConfig.builder().maxRetries(3)方法叫 maxAttempts，且含首次尝试.maxAttempts(3) = 1 次首发 + 2 次重试
