00 · 学习地图

先花 12 分钟把「这个站怎么用、章节为什么这么排、你需要先会什么」看清楚，比直接扎进代码省的时间多得多。

为什么要再造一个文档站

AgentScope Java 的官方文档（就在仓库里 docs/v2/zh/docs/**）其实写得相当扎实，但它有三个身不由己的立场问题，初学者很容易在第 1 小时就卡住：

官方文档的立场 初学者遇到的后果 本站怎么处理
按能力组织（agent / tool / model 各一篇） 看完 agent 篇还是不知道下一步该干嘛；一篇里同时出现 HarnessAgent、ReActAgent、RuntimeContext， 谁包着谁要自己猜 按学习顺序重排：先能跑 → 再懂调用链 → 最后碰扩展点
假设你懂 Project Reactor 第一个例子结尾的 .block() 是什么、为什么少了它就没输出、为什么在 Swing/JavaFX 线程里调用会卡死，全靠试 单开一章只讲这个框架真正用到的响应式概念（03），其余章节遇到就回链过去
默认你已经在生产环境、知道该选哪个模块 不知道该引 agentscope-core 还是 agentscope-harness，也不知道模型 provider 为什么要单独一个模块 把「装错依赖」列为第一章主内容，并给出报错与依赖的对照表

另外你在官网上看到的部分部署页（/deploy/**）示例是 Python 的，那是另一条产品线的文档串了 进来。本站只认 Java，只认 2.0.4。

三条学习主线：同一章读三遍

每一章都被切成三种可读法。你不必一次全读，但别只读第一种——只照抄不改，两周后还是不会。

① 跟做线 「读完你能做到」+「最小可跑」+「逐行解读」。目标：10 分钟内看到程序真的输出东西。
→
② 理解线 「端到端一次运行发生了什么」+「API 速查表」。目标：知道数据在哪个环节变成什么样。
→
③ 避坑线 「陷阱与窍门」+「自检三问」+「动手练习」。目标：出错时能自己定位到具体参数。

实际建议：第一遍只走 ①，把代码跑起来；第二天通勤路上读 ②；等你真的撞到错误，再回来读 ③ 和附录 B。这时候的阅读量吸收率最高，因为你带着问题来。

章节依赖图：为什么是这个顺序

00 学习地图 → 01 环境与依赖 → 02 第一个 Agent
这三章是「必须按顺序」的。01 解决「编译不过」，02 解决「跑起来了但看不懂发生了什么」。
03 响应式必修
放在 02 之后而不是之前：先让你抄成功一次，再解释那段抄成功的代码为什么必须写 .block()。顺序反过来会在纯理论上耗光耐心。
04 消息与事件 → 05 模型层
这两个是框架的「名词表」。04 讲 Msg 与事件，后面所有章节的返回值、流式、工具调用都建立 在这两个概念上，所以紧跟在 03 后面。
06 工具系统
Agent 之所以是 Agent 而不是「一段 HTTP 调用」，全靠这一章。它依赖 04（工具调用是消息里的内容块） 和 05（工具的 schema 要交给模型）。
07 记忆与上下文 → 08 权限与 HITL
07 让 agent 跨调用「记得」，08 决定它「能做不该做的事吗」。这两个是把它从 demo 变成能给别人用的东西 的分水岭。
09 Middleware 与 Hook → 10 ReAct vs Harness → 11 综合案例
09 是「插手框架」的扩展点，必须等你熟悉默认流程之后才讲。10 反过来做选型总结，11 把前 10 章串成一个完整小程序。
12 工作区 → 13 沙箱 → 14 子 Agent / 团队 → 15 压缩与记忆 → 16 技能 → 17 计划模式与 MCP → 18 网关与消息总线
这七章是「把 demo 变成工程」的一层，前提是 11 章已经有一个能跑的小项目。12 给它手（文件与工作区），13 把命令关进容器，14 让它学会分工，15 保证上下文不爆，16、17 管「它能做什么」，18 把它接到真实渠道上并解决「后台任务的结果怎么回来」。这七章彼此独立可单读，但都建立在 04（消息）、07 （状态）与 09（中间件）之上。
19 服务化 → 26 生产运维
这八章把 11 章的小项目变成可登录、可发布、可编排的服务：19 起站与第一个 Managed Agent，20 把 Agent 发布成 Endpoint，21 拆 Agent 定义与四类资源，22 接 External Agent，23 接 Hosted Agent，24 组 Team， 25 写 Workflow / Automation / Issue 闭环，26 用 Helm、共享存储与备份把它放进生产。读之前至少完成 09（Hook）与 11（综合案例）。
27 扩展地图 → 36 基础设施与生态
这十章按「出站能力 → 入站入口 → 外围设施」展开：27 先画扩展地图，28 模型，29 记忆，30 分布式存储， 31 Agent 状态，32 RAG，33 协议，34 渠道，35 技能仓库，36 Nacos / Higress / Scheduler / Studio / Training。它们更像查阅手册，不必顺序读；每章都能单独落到一个接口、一个 artifact 或一条部署边界。 要直接落地看 36A，要查依赖坐标看附录 F。
可以跳的例外

如果你写过 Spring WebFlux，03 可以只看「死锁」那一节就跳过；如果你已经在用别家的 tool 注解，06 可以直接看「ToolGroup 与 Meta Tool」。其余章节请按顺序。

前置知识自查：这些不会会卡在哪

知识点 框架在哪用到 不会的替代做法
JDK 17（record、密封类、switch 表达式、文本块 """） 依赖与编译的硬要求：pom.xml:33 写着 <java.version>17</java.version>；示例里大量用文本块写提示词 把文本块改成普通字符串拼接即可，其它不影响
Maven 依赖与 <dependency> 01 章全部 照抄本站给的 XML 片段，改 <version> 就行
Lambda 与方法引用 streamEvents(msg).doOnNext(event -> ...)、subagentFactory(name, () -> agent) 可以，但会非常痛苦；建议先花 20 分钟补
Project Reactor 的 Mono / Flux 所有 call() / streamEvents() 的返回值 03 章就是为这个准备的，只讲用得上的那部分
环境变量与 API Key 模型调用；DASHSCOPE_API_KEY 之类由框架自动读取 也可以用 builder 显式传 key，见 05 章
JSON / Jackson JsonNode 结构化输出、工具参数 schema 06 / 05 章给了不碰 Jackson 的最小写法

想一分钱不花跑通

框架把每个模型提供商做成独立模块，其中有 agentscope-extensions-model-ollama——本地 Ollama 起一个模型就能跑，把 .model("dashscope:qwen-plus") 换成 .model("ollama:llama3") 即可（这个字符串形式由 ModelRegistry 解析，见 05 章）。02 章的例子的逻辑与费用无关，换成 ollama 一样能验证「第二轮记得第一轮」。

每一章的固定结构与图例

早期章节基本按同构的 10 段写；19 章之后主题变长，段落名会变，但读法不变：目标 → 为什么 → 最小可跑 → 端到端 → 速查 → 陷阱 → 自检 → 练习 → 下一步。认准这些功能，而不是标题字面。

  1. 读完你能做到
    3 条可验证目标，动词开头。做不到就别往下读。
  2. 先说为什么
    这个能力解决什么痛点。不先抛术语。
  3. 最小可跑
    完整文件，含 import，复制即编译。
  4. 逐行解读
    只解读容易懵的行，不废话。
  5. 端到端：一次运行发生了什么
    把调用链摊开成时间轴 / 目录树。
  6. API 速查表
    参数、类型、默认值，每个关键值带源码出处。
  7. 陷阱与窍门
    「你会看到 X → 因为 Y → 改成 Z」三段式。
  8. 自检三问
    答案折叠，先自己想再点开。
  9. 20 分钟动手练习
    一个具体小改造 + 应该看到什么现象。
  10. 下一步 / 关联源码
    该读哪一章、该翻哪个文件。

怎么算学完一章

每章底部的「标记本章已读完」会记下时间，练习勾选也计入进度；练完最后一步时按钮会自己点亮。读完超过一周，页面会提醒回看本章的陷阱与速查表。首页进度卡把「练完还没标记读完」「练习还差几步」「该复习了」排成最多 3 条待办，也能把进度导出成 JSON，换台机器接着学。

事实来源：我怎么保证不编

写每一章时的流程是固定的：先在 docs/v2/zh/** 找到官方说法 → 再打开对应的 .java 源码确认签名、默认值、判定分支 → 若两者冲突，以源码为准并在页面上指 出差异。任何我没能定位到源码的数字，页面上只会写「取决于配置」，不会给一个看起来很像的默认值。

路径约定：所有出处标签里的路径都相对于 Java 仓库根目录（也就是你工作区里的 agentscope-java-2.0.4/）。复制出来得到 pom.xml:30 这样的相对路径，在你的 IDE 里 Ctrl+Shift+N 双击搜文件名即可打开；Ctrl+点击则直接跳到上游 github.com/agentscope-ai/agentscope-java。
