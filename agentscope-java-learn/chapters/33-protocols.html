33 · 协议：A2A / Agent Protocol / AG-UI

第 20 章的 Endpoint 是平台自己的调用契约；这一章讲三种「标准协议」适配器。它们不是同一个接口的三种写法， 而是三个不同边界：A2A 让 Agent 之间互调，Agent Protocol 让业务系统按任务 HTTP 提交，AG-UI 把事件流推给前端。 选错协议，最先出问题的不是代码，而是信任边界与状态归属。

读完你能做到

  • 用「谁调用谁、传输什么、默认入口是什么」三句话区分 A2A、Agent Protocol 与 AG-UI
  • 把远端 A2A Agent 包成本地 Agent，或把本地 ReActAgent 暴露成 A2A Server
  • 说清 Agent Protocol 的 /tasks、等待、取消、SSE 与 HITL resume 的完整链路
  • 配置 AG-UI 的 path、agent 路由、工具合并、token usage 与 interrupt-on-disconnect
  • 识别三处默认值 / 命名差异，尤其是 A2A starter 的 artifact 名
  • 按部署形态选择协议，并说清 CORS、forwardedProps、任务存储与并发边界

三条边界，不是三个 endpoint

官方把三种协议按信任边界分开：AG-UI 面向用户 UI 的事件流，Agent Protocol 是内部远程子 Agent / 任务 HTTP 面， A2A 用于外部 Agent 互操作 overview.md:6-22。 这三句话决定了它们的入口、事件格式和默认安全假设。

A2A：客户端把远端 Agent 变成本地 Agent

A2A 模块分客户端与服务端，两个子模块完全独立，可以只用其一 a2a.md:6-11。 客户端侧，A2aAgent 是 AgentBase 的子类，可以像普通 Agent 一样放进 Pipeline、MsgHub 或 Subagent a2a.md:25-62。 

A2aAgent remote = A2aAgent.builder()
    .name("remote-translator")
    .agentCard(card)
    .build();

Msg result = remote.call(new UserMessage("Translate to English: 你好")).block();

没有现成 AgentCard 时，可以用 WellKnownAgentCardResolver 从 /.well-known/agent-card.json 拉取 a2a.md:45-54。 这适合「对方已经按 A2A 标准暴露发现文档」的场景；否则直接传 card 更可控。

A2A 服务端：只组装处理器，不监听端口

AgentScopeA2aServer 负责构建组件和请求处理链，本身不监听端口、不暴露 endpoint； 具体监听由你的 Spring / Quarkus / Vert.x 完成 a2a.md:64-100。 它默认用内存 TaskStore、QueueManager 与 push config；生产要换成持久化实现 AgentScopeA2aServer.java:241-287。 

AgentScopeA2aServer server = AgentScopeA2aServer.builder()
    .agentBuilder(ReActAgent.builder().name("backend-agent").model(model))
    .transportProperties(new JsonRpcTransportProperties())
    .build();

TransportWrapper wrapper = server.getTransportWrapper("JSONRPC");
// 交给你的 Web 框架转发
server.postEndpointReady();   // Web 服务就绪后再注册

没有指定 transport 时，builder 默认尝试 JSONRPC；如果连默认 transport 的 properties 都找不到， 直接抛 IllegalArgumentException AgentScopeA2aServer.java:383-395。 postEndpointReady() 会触发 AgentCard 注册，顺序不能反 AgentScopeA2aServer.java:161-162。

A2A starter 名与文档不一致

A2A 文档写的是 agentscope-spring-boot-starter-a2a-server a2a.md:108-110， 但仓库里实际的 artifact 是 agentscope-a2a-spring-boot-starter pom.xml:28。 照文档写依赖会解析失败。

Agent Protocol：/tasks 是任务 API，不是聊天 UI

Agent Protocol 把 Harness Agent 暴露成标准 HTTP 任务接口，适合 CI、其他 Agent 平台、自动化任务，以及远程子 Agent 的托管端 agent-protocol.md:6-13。 它由 Spring Boot 自动配置提供，默认关闭：不打开 agentscope.agent-protocol.enabled 就不会注册任何 REST 接口 AgentProtocolProperties.java:25-32。

端点作用关键点
POST /tasks提交任务必须带 task_id；成功返回 pending
GET /tasks/{id}快照状态、结果、错误、待确认项
GET /tasks/{id}/wait阻塞等待timeout_seconds 默认 7200 秒
POST /tasks/{id}/cancel请求取消不是删除记录
GET /tasks/{id}/eventsSSE 事件流from_seq / Last-Event-ID 续传
POST /tasks/{id}/resumeHITL 恢复提交 decisions，成功返回 running

端点与默认等待时间来自控制器实现 AgentProtocolController.java:59-109 AgentProtocolController.java:126-137。

Agent Protocol 的状态：pending、running、success、error、cancelled

提交后任务先进入 pending，开始执行变 running；完成、失败、取消分别映射成 success、error、cancelled。 等待工具确认时，快照会显示 awaiting_confirm，但底层存储的 TaskStatus 仍是 RUNNING， 所以父侧 barrier 会继续等 agent-protocol.md:218-226 AgentProtocolTaskStore.java:577-584。

SSE 的详细度由提交时的 context.detail 控制，默认 status，再往上依次是 full 与 verbose；只有 verbose 能完整复现 Agent 自身事件流 agent-protocol.md:241-251。 每条事件带 eventType 与 payload，客户端可以只读扁平字段，也可以还原原始事件 agent-protocol.md:253-260。

HITL 恢复时，decisions 按 toolCallId（也接受 tool_call_id）给出 approved 与可选 reason；只有 hitl-enabled=true 时才会因工具确认暂停 agent-protocol.md:262-275。

Agent Protocol 配置：任务 Store 与 workspace 分开

三个最关键的默认值：enabled=false、streaming-enabled=true、 hitl-enabled=true；SSE 回放缓冲默认 256 条，sse-timeout-ms 默认 10,800,000 毫秒， 但源码注释说明它是客户端 idle hint、默认不由服务端强制 AgentProtocolProperties.java:25-45。 

agentscope:
  agent-protocol:
    enabled: true
    streaming-enabled: true
    hitl-enabled: true
    sse-replay-buffer-size: 256
    sse-timeout-ms: 10800000
    # task-store-path 是协议控制面目录，不是 Agent workspace
    # task-store-path: ${user.dir}/.agentscope/agent-protocol

任务记录由 ProtocolTaskRepository 持久化，默认落在 ${user.dir}/.agentscope/agent-protocol；它和每个 Agent 的 WorkspaceManager （MEMORY、sessions、skills）完全独立 agent-protocol.md:52-64 AgentProtocolProperties.java:91-97。 把两者混用，会出现「任务元数据写进了执行工作区」或「清理 workspace 把任务记录删了」。

AG-UI：把 AgentEvent 映射成前端事件流

AG-UI 把 AgentScope 的 AgentEvent 转成 AG-UI 事件，覆盖文本、推理、工具调用、状态、自定义事件、 token usage 与 HITL interrupt agui.md:6-22。 手动使用时，构造 AguiAgentAdapter，把 RunAgentInput 转成事件流 agui.md:46-67。 

AguiAdapterConfig config = AguiAdapterConfig.builder()
    .enableReasoning(true)
    .emitTokenUsage(true)
    .runTimeout(Duration.ofMinutes(5))
    .build();

AguiAgentAdapter adapter = new AguiAgentAdapter(agent, config);
Flux events = adapter.run(runAgentInput);

事件映射有固定语义：AgentStartEvent → RUN_STARTED， AgentEndEvent → RUN_FINISHED，文本走 TEXT_MESSAGE_*， 工具调用走 TOOL_CALL_*，未映射事件回退成 RAW agui.md:69-85。 RUN_ERROR 与 RUN_FINISHED 是互斥终态；只有旧客户端才需要 emitRunFinishedAfterError=true 补一个完成事件。

AG-UI starter：path、路由与工具合并

Spring Boot starter 的默认入口是 POST /agui/run，启用 path routing 时还有 /agui/run/{agentId}；agent 也可以从 X-Agent-Id 头读取 AguiRestController.java:84-110。

配置默认含义
path-prefix/agui入口前缀
cors-enabled / cors-allowed-originstrue / *默认放开所有来源，生产要收窄
run-timeout10 分钟单次 run 上限
default-agent-iddefault请求未指定 agent 时使用

这些默认值在 AguiProperties 里逐项定义 AguiProperties.java:49-130； 另有 maxThreadSessions=1000、sessionTimeoutMinutes=30、sseTimeout=600000 只在 server-side memory 或 SSE 场景生效。

前端可以在 RunAgentInput.tools 里传工具 schema。默认 ToolMergeMode 是 MERGE_EXTERNAL_PRIORITY：合并两侧工具，同名时前端优先；EXTERNAL_ONLY 只暴露前端工具， AGENT_ONLY 忽略前端工具 agui.md:254-264 AguiProperties.java:61-62。

AG-UI 的 HITL：interrupt 与 resume

工具挂起 / 外部执行、权限确认都会在 RUN_FINISHED 上输出官方 interrupt， reason 固定为 "tool_call"，因为 interrupt 绑定到具体 toolCallId agui.md:266-273。 前端完成后，在同一个 threadId 的下一次 run 里带回 resume[]，包含 interruptId、status 与 payload agui.md:314-336。

权限确认只有 payload.approved 严格为布尔 true 才批准； editedArgs 如果存在，必须是对原始参数的完整替换，不是局部 merge agui.md:338-340。 这比「传一个 partial patch」更安全，也更符合「参数整体可审计」的要求。

安全边界：CORS、forwardedProps 与任务目录

AG-UI 默认 cors-enabled=true 且允许 *，适合本地开发；生产应显式收窄到前端域名 AguiProperties.java:52-56。 forwardedProps 来自客户端请求体，不能当身份来源；身份应由认证链路或服务端 resolver 注入 agui.md:252。

Agent Protocol 的 context.attributes 也是调用方数据，整体挂在命名空间键下，避免覆盖框架自身读取的 agentId / outboundAddress 等保留键；这些属性不会写进系统提示词 agent-protocol.md:116-127。 需要提升为顶层键时，用显式白名单的 RuntimeContextCustomizer。

A2A 服务端默认的 TaskStore / QueueManager 都是内存实现，进程重启就丢；生产要换成持久化实现， 否则「任务提交成功」只在当前进程生命周期内成立 AgentScopeA2aServer.java:241-287。

并发与会话：同一个 agent 实例可以服务多个任务

Agent Protocol 的 Agent 在调用之间是无状态的，单例即可服务多个并发任务；每个任务通过 RuntimeContext 携带独立的 (userId, sessionId)，同 session 的并发请求会串行化，不同 session 并行 agent-protocol.md:66-80。 但 AgentFactory 在并发任务下应返回独立实例，返回 null 会让任务以错误状态结束 agent-protocol.md:112-114。

AG-UI 把 threadId 映射成 sessionId，同一个 Agent 实例在不同 thread 之间保持会话隔离 agui.md:188-205。 默认 server-side-memory=false：不按 threadId 保留 Agent 实例，历史是否连续取决于你传入的消息与状态。

六个坑：把协议当框架

坑一：以为 A2A Server 会自己监听端口。它只组装处理器，端口由你的 Web 框架负责 a2a.md:100。

坑二：照文档写 A2A starter 名。实际 artifact 是 agentscope-a2a-spring-boot-starter，不是文档里的 agentscope-spring-boot-starter-a2a-server pom.xml:28。

坑三：Agent Protocol 没开 enabled。默认 false，不配置就不会有 /tasks AgentProtocolProperties.java:25-26。

坑四：假设 AG-UI 一定补 RUN_FINISHED。正常流结束但上游没发 AgentEndEvent 时，adapter 不会补 agui.md:85。

坑五：把 forwardedProps 当身份。它来自客户端请求体，不能作为可信身份来源 agui.md:252。

坑六：把任务 Store 指到执行 workspace。协议任务元数据与 Agent workspace 必须分开，清理 workspace 不应删任务记录 agent-protocol.md:52-64。

自测：三个判断题

A2A Server 构建完成后，是否已经在监听端口？

没有。它只构建组件与请求处理链，具体监听由你的 Web 框架完成；postEndpointReady() 只是在服务就绪后触发注册 a2a.md:100 AgentScopeA2aServer.java:161-162。

引入 Agent Protocol 依赖后，/tasks 会自动出现吗？

不会。它默认 enabled=false，必须在配置里显式打开，才会注册 REST 接口 AgentProtocolProperties.java:25-26。

AG-UI 默认会把 reasoning 和 token usage 发给前端吗？

不会。两者默认都关闭，需要显式设置 enable-reasoning=true 与 emit-token-usage=true AguiProperties.java:70-80。

练习：给三个调用方各选一条协议

目标不是把三个协议都跑通，而是能说清「谁调用、怎么等结果、断线怎么办」。建议 50 分钟：

  1. 列三个调用方
    浏览器聊天 UI、CI 任务系统、另一个 Agent 平台；分别写下它们要同步结果还是事件流。
  2. 选协议
    分别映射到 AG-UI、Agent Protocol、A2A，并写一句为什么不是另外两个。
  3. 配 AG-UI
    打开 starter，设置 path、agent-id-header 与 CORS 白名单；发一次 run，确认收到 RUN_STARTED / TEXT / RUN_FINISHED。
  4. 配 Agent Protocol
    设置 enabled=true，提交一个 task，轮询快照，再用 wait 等终态。
  5. 测 SSE 续传
    在事件流中途断开，用 from_seq 或 Last-Event-ID 重连，确认补发范围。
  6. 测 A2A 客户端
    用 AgentCard 或 well-known resolver 连接一个远端 Agent，像本地 Agent 一样 call。
  7. 记录默认值
    把三个协议的关键默认值抄进一张表：端口 / 入口、等待时间、CORS、超时、存储。
  8. 写三行结论
    分别写「谁调用谁」「结果怎么拿」「断线/重启后什么会丢」，确保每行都能在配置或源码里找到证据。
