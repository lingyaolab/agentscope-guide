36A · 集成落地手册：七条链路从配置到验收

第 36 章回答「每个扩展接在哪一层」，这一页回答「真正接起来要做哪几步」。 七个 playbook 互相独立：Nacos A2A、Nacos Prompt / Skill、Higress、Scheduler、Studio、Training、Chat Completions。 每条都给最小配置、能编译的调用形状、验收标准和最常见的失败点；它们是第 36 章的配套子页，不重复讲完整背景。

单主题深挖

需要更细的排障与配置时，直接看分册： 36A-1 Nacos A2A · 36A-2 Higress · 36A-3 Scheduler · 36A-4 Studio HITL · 36A-5 Training。

读完你能做到

  • 把 A2A AgentCard 真正注册到 Nacos，并让另一个进程按名字解析出来
  • 用 starter 或直接 listener 接 Prompt，知道版本 / 标签为什么只生效一次
  • 让 Nacos Skill 出现在 Agent 的技能列表里，而不是只让 getSkill 能调用
  • 用 Higress 的 MCP 客户端与工具搜索接上网关工具，并验证工具真的进了 Toolkit
  • 分清 Quartz 与 XXL-Job 谁真正持有调度状态，跑通一次触发与一次暂停
  • 开 Studio 看最终消息与 HITL，开 Training 跑一条被标记的样本并完成 commit
  • 用 starter 暴露 OpenAI 兼容接口，验证普通 JSON、SSE 与工具调用往返

Playbook 1：Nacos A2A 注册与发现

服务端做两件事：把 AgentCard 发布到 Nacos，再把 Transport 端点注册成 Endpoint。 NacosAgentRegistry 是 A2A 服务端与 Nacos 之间的适配器；它的 builder 接收 AiService 或 Nacos Properties，nacosA2aProperties 可选 NacosAgentRegistry.java:250-306。 

NacosAgentRegistry registry = NacosAgentRegistry.builder(nacosProperties)
    .nacosA2aProperties(NacosA2aRegistryProperties.builder().build())
    .build();

AgentScopeA2aServer server = AgentScopeA2aServer.builder(agentBuilder)
    .agentCard(agentCard)                 // ConfigurableAgentCard
    .withAgentRegistry(registry)          // 注意不是 agentRegistry(...)
    .deploymentProperties(8080)
    .build();
文档这里又少了一个 with

官方 Nacos 页写的是 AgentScopeA2aServer.builder().agentRegistry(...) nacos.md:107-110， 但源码里 builder 必须传 ReActAgent.Builder 或 AgentRunner，注册方法叫 withAgentRegistry(...) AgentScopeA2aServer.java:174-184 AgentScopeA2aServer.java:333。 按文档写会编译失败。

客户端只拿 AgentCardResolver：构造器是 (Properties) 或 (AiService)， Agent 名由 A2aAgent.builder().name(...) 提供。解析器内部会缓存并按 Nacos 事件更新 NacosAgentCardResolver.java:75-98。 

NacosAgentCardResolver resolver = new NacosAgentCardResolver(nacosProperties);

A2aAgent translator = A2aAgent.builder()
    .name("translator")
    .agentCardResolver(resolver)
    .build();

验收：在 Nacos 控制台能看到 AgentCard 与 Endpoint；另一个进程用 resolver 能拿到卡； 调用远端 Agent 时 URL 指向注册的 Transport，而不是写死的地址。注册是显式动作，新版本上线要再调一次。

Playbook 2：Nacos Prompt 与 Skill

Spring Boot 直接用 agentscope-nacos-spring-boot-starter，Prompt 前缀是 agentscope.nacos.prompt；enabled 默认 true，sys-prompt-key 指向 Nacos 的 promptKey，version 与 label 互斥，variables 用于渲染 AgentScopeNacosPromptProperties.java:53-81。 

agentscope:
  nacos:
    prompt:
      enabled: true
      sys-prompt-key: system-prompt
      version: "1.2.0"          # 或 label: stable，不要同时写
      variables:
        userName: Alice

非 Spring 场景直接用 NacosPromptListener：第一次按 promptKey 订阅，之后 Nacos 推送会写回本地缓存 NacosPromptListener.java:37-68。 但缓存只按 promptKey 命中；第二次换 version / label 不会重新订阅 NacosPromptListener.java:112-138。 

NacosPromptListener prompts = new NacosPromptListener(aiService);

String tpl = prompts.getPrompt(
    "system-prompt",
    "1.2.0",                  // version
    null,                     // label，与 version 互斥
    Map.of("userName", "Alice"),
    "你是一个助手");           // 找不到时的默认值

Skill 侧要把 Nacos 里的 ZIP 当成只读仓库。构造器签名是 (AiService, namespaceId, Properties, knownSkillNames)；命名空间为空按 public 处理， version / label 的解析顺序是 Properties → JVM -D → 环境变量，版本优先 NacosSkillRepository.java:136-158 NacosSkillRepository.java:49-52。 

Properties props = new Properties();
props.setProperty(NacosSkillRepository.SKILL_VERSION_PATH, "1.2.0");

NacosSkillRepository repo = new NacosSkillRepository(
    aiService,
    "public",
    props,
    List.of("calculator", "translator"));   // 不给名单，getAllSkills() 返回空

验收：改一次 Prompt 模板，下一次 getPrompt 能看到新内容； Nacos 里加一个技能名到名单后，getAllSkills() 能返回它，而不只是 getSkill 能下载。 技能仓库只读，save / delete 返回 false 是预期行为。

Playbook 3：Higress MCP 工具

Higress 的 builder 有两种端点：SSE 与 StreamableHTTP；请求超时默认 120 秒，初始化超时 30 秒 HigressMcpClientBuilder.java:71-82。 它没有 build()，只有 buildAsync() 与 buildSync() HigressMcpClientBuilder.java:311 :357。 

HigressMcpClientWrapper client = HigressMcpClientBuilder
    .create("higress")
    .streamableHttpEndpoint("http://gateway/mcp-servers/union-tools-search")
    .toolSearch("退款", 8)          // 只返回语义相关 Top 8；默认 Top 10
    .buildSync();

HigressToolkit toolkit = new HigressToolkit();
toolkit.createToolGroup("knowledge", "知识库工具");

toolkit.registration()
    .mcpClient(client)
    .enableTools(List.of("search-doc", "fetch-url"))
    .group("knowledge")
    .apply();

工具搜索默认关闭；开启后 listTools() 会先调 x_higress_tool_search， 只返回相关工具，并把结果缓存在 wrapper 里供 getCachedTool 使用 HigressMcpClientWrapper.java:156-204。 registerMcpClient 返回 Mono<Void>；registration().apply() 内部会完成注册并等待结果 HigressToolkit.java:99-120。

验收：toolkit.getHigressMcpClient() 非空；listTools() 返回的工具名与白名单一致；Agent 实际调用一个只读工具成功。鉴权、限流、路由留在 Higress，不要在 Java 侧重复。

Playbook 4：Quartz 与 XXL-Job

先分清职责：Quartz 在 Java 进程内持有 Trigger；XXL-Job 只把 Agent 注册成 JobHandler，调度在 admin 控制台。 两者共用 AgentScheduler.schedule(...) 形状，但能力不同。

Quartz：显式给模式，别用默认 NONE

QuartzAgentScheduler scheduler = QuartzAgentScheduler.builder()
    .schedulerId("daily")
    .autoStart(true)
    .build();

ScheduleConfig cfg = ScheduleConfig.builder()
    .cron("0 0 8 * * ?")
    .zoneId("Asia/Shanghai")
    .build();

scheduler.schedule(agentConfig, cfg);
scheduler.pause("DailyReportAgent");    // 只有具体 Quartz 类型有
scheduler.resume("DailyReportAgent");

autoStart 默认 true，Job 组是 agentscope-quartz；CRON / FIXED_RATE / FIXED_DELAY 分别映射为不同 Trigger QuartzAgentScheduler.java:626-629 QuartzAgentScheduler.java:246-305。 但便利方法 schedule(agentConfig) 用的是 NONE，不会建 Trigger QuartzAgentScheduler.java:154-156。

XXL-Job：只注册，控制台排程

XxlJobSpringExecutor executor = new XxlJobSpringExecutor();
executor.setAdminAddresses("http://localhost:8080/xxl-job-admin");
executor.setAppname("agentscope-demo");
executor.setAccessToken("xxxxxxxx");
executor.start();

AgentScheduler scheduler = new XxlJobAgentScheduler(executor);
scheduler.schedule(agentConfig, ScheduleConfig.builder().build()); // 只接受 NONE

XXL-Job 实现传非 NONE 模式会抛 UnsupportedOperationException；cancel 也不支持， 要去控制台暂停或删除 Job XxlJobAgentScheduler.java:148-161 :289-304。

验收：Quartz 看本地日志出现第一次触发，pause 后不再触发、resume 后恢复； XXL-Job 控制台能看到以 Agent 名命名的 JobHandler，并在控制台配置 CRON 后触发一次。

Playbook 5：Studio 消息与 HITL

StudioManager.init() 会建 HTTP / WebSocket 客户端、注册 run、连接 WebSocket；成功后自动 addSystemHook 并注册 Tracer StudioManager.java:214-260。 所以初始化后不要再手动加 StudioMessageHook。 

StudioManager.init()
    .studioUrl("http://localhost:3000")
    .project("MyProject")
    .runName("experiment_001")
    .initialize()
    .block();

StudioUserAgent reviewer = StudioUserAgent.builder()
    .name("Reviewer")
    .studioClient(StudioManager.getClient())
    .webSocketClient(StudioManager.getWebSocketClient())
    .inputTimeout(Duration.ofMinutes(10))   // 默认 30 分钟
    .build();

StudioUserAgent 会发 requestUserInput，等 Studio 侧输入；默认超时 30 分钟 StudioUserAgent.java:237-327。 消息 Hook 只推 PostCallEvent 的最终消息，不覆盖每条 token StudioMessageHook.java:66-95。

验收：一次 agent.call() 后 Studio 只出现一条最终消息；HITL 场景能看到输入框并暂停； 生产 Profile 关闭 Studio 后，调用不再产生推送，退出时调 StudioManager.shutdown() 释放连接。

Playbook 6：Training 采样与 commit

Training 是影子流量：命中采样后克隆 Agent、换 TrinityModelAdapter 异步跑一遍， 生产响应不等它完成 TrainingRouter.java:221-249 :277-298。 commitIntervalSeconds 默认 300；stop() 会做最后一次 commit 并移除 Hook TrainingRunner.java:139-168。 

TrainingRunner runner = TrainingRunner.builder()
    .trinityEndpoint("http://localhost:8080")
    .modelName("/path/to/model")
    .selectionStrategy(ExplicitMarkingStrategy.create())  // 只训练显式标记
    .rewardCalculator(agent -> 1.0)
    .commitIntervalSeconds(300)
    .build();

runner.start();

agent.call(msg)
    .contextWrite(TrainingContext.mark("prod", "high-quality"))
    .block();

runner.stop();

ExplicitMarkingStrategy.create() 的标记 TTL 是 1 分钟 ExplicitMarkingStrategy.java:58-70； TrainingContext.mark(...) 通过 Reactor Context 传播 TrainingContext.java:81-137。 不传策略时默认 10% 采样；commitIntervalSeconds <= 0 会关闭定时 commit TrainingConfig.java:125-137 TrainingRunner.java:185-214。

验收：只有带 TrainingContext.mark 的调用进入样本；日志出现 reward / feedback； commit 周期到达时看到 commit 成功；stop() 后再调 Agent 不再触发训练。

Playbook 7：Chat Completions Web

核心适配器只做事件转换，HTTP / SSE 由 starter 提供。starter 默认路径是 /v1/chat/completions，默认启用 ChatCompletionsProperties.java:34-41。 

agentscope:
  chat-completions:
    enabled: true
    base-path: /v1/chat/completions

Controller 用 ObjectProvider<ReActAgent> 取 Agent；核心 starter 默认提供的是 singleton bean，所以每次 getObject() 拿到的是同一个实例 ChatCompletionsWebAutoConfiguration.java:36-37 :139-148。 自己写 Controller 时，核心适配器签名是 stream(ReActAgent, List<Msg>, requestId, model)，请求先由 ChatMessageConverter.convertMessages(...) 转成消息列表 ChatCompletionsStreamingAdapter.java:86-104。 

ChatCompletionsStreamingAdapter adapter = new ChatCompletionsStreamingAdapter();
List<Msg> messages = converter.convertMessages(request.getMessages());

Flux<ChatCompletionsChunk> chunks = adapter.stream(
    agent, messages, requestId, request.getModel());

验收：curl 普通 JSON 返回 choices；stream=true 或 Accept: text/event-stream 返回 SSE 并以 data: [DONE] 结束 ChatCompletionsStreamingService.java:79-83； 带工具的请求把 tool_calls 返回给客户端，由客户端执行后回填下一轮 ChatCompletionsRequest.java:74-81。
