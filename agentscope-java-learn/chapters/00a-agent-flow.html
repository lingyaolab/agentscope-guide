00A · 信息流实验室：一条消息怎么走完 Agent

读代码时最容易断片的地方，是「这一步的输出到底交给了谁」。这一页把 AgentScope 的一次调用拆成可播放的节点： 从一条 Msg 进入，到模型、工具、状态、事件，再到 Harness 与外围设施。 三档场景从最小 ReAct 到全依赖，可以逐步看，也可以自动播放。

这一页怎么用

  • 用「最小」场景看清 L1 的 9 个基础节点，以及每个节点吐出什么
  • 用「工程化」场景看 L2 在 L1 上新增的 5 个节点：RuntimeContext、Workspace、Sandbox、Subagent、Event
  • 用「全依赖」场景看 L3 在 L2 上新增的 8 个外围节点，以及它们接在哪个位置
  • 用「上一步 / 下一步 / 播放」把信息流走一遍，而不是只看一张静态图
  • 知道每一步应该看哪一章、哪个源码入口

最小链路：一次 ReAct 调用

        

          L1 只有 9 个节点：消息进来，拼上下文，模型决定「说话还是调工具」，工具结果回填后再让模型收尾。
          这条链路里没有 Workspace、没有沙箱、没有子 Agent，也没有 Gateway。
        

        

          

            
              
节点它做什么输出给谁

            
            
              
Msg用户输入的统一消息结构ReActAgent.call

              
ReActAgent拼历史、system prompt 与工具 schemaMiddleware / Formatter

              
Formatter把 Msg 翻译成厂商需要的 JSONModel

              
PermissionEngine决定工具调用是放行、询问还是拒绝ToolExecutor / HITL

              
ToolExecutor执行工具，产出 ToolResultBlock下一轮 Model

              
AgentStateStore保存本轮状态；事件流同时对外发出调用方 / 下一个请求

            
          

        


        
工程化：在 L1 上加了什么

        

          L2 不是另起一条链路：它在 L1 的 9 个节点上新增 5 个，共 14 个。新增的是
          RuntimeContext、Workspace、Sandbox、Subagent、Event；
          HarnessAgent 不重写 ReAct 循环，而是在它外面加壳，信息流还是同一条。
        

        

          

            
              
L2 的层插在哪它改变什么

            
            
              
RuntimeContext +L2进入 Agent 之前userId / sessionId / 会话状态与请求级上下文

              
Workspace 投影 +L2system prompt 之前把 AGENTS.md、技能、文件说明投进上下文

              
Middleware 链模型与工具前后压缩、技能、计划模式、权限、动态工具面

              
Sandbox / Filesystem +L2工具执行时把文件与命令关进隔离环境

              
Subagent / Team +L2工具调用内把一部分工作委派给另一个 Agent

              
Event / Hook +L2Agent 之外生命周期事件、日志、推送与后续网关

            
          

        


        
全依赖：在 L2 上再接什么

        

          L3 在 L2 的 14 个节点上再加 8 个，共 22 个：Scheduler、Inbound、Gateway、Nacos、Higress、Studio、Training、Outbound。
          注意它们不是都塞进 ReAct 循环：Nacos 在配置 / 注册层，Higress 在工具层，Scheduler 在触发层，
          Studio 与 Training 在旁路。
        

        

          

            
              
外围设施接在哪对信息流的影响

            
            
              
Channel / Chat Completions / Endpoint入站把平台事件或 OpenAI 请求转成 Msg

              
Gateway入站之后选 Agent、定会话、给同一会话排队

              
Nacos启动 / 配置Prompt、Skill、A2A 注册发现

              
Higress工具面MCP 工具与工具搜索

              
Studio旁路最终消息、trace、HITL

              
Training旁路采样后跑影子 Agent，再 feedback / commit

              
Scheduler触发没有人类消息，也能按时间造一次调用
