36A-4 · Studio HITL：消息、trace 与真人输入

Studio 有三个容易混的能力：消息推送、trace、Human-in-the-Loop。它们不是同一条通道： StudioMessageHook 只推一次调用的最终消息，trace 由 telemetry 负责，HITL 由 StudioUserAgent / requestUserInput 等真人输入。

读完你能做到

  • 正确初始化 Studio，知道它自动挂了什么
  • 说清消息 Hook 究竟推哪些消息，哪些要看 trace
  • 用 StudioUserAgent 做一次真人输入并设置超时
  • 在生产环境按开关关闭 Studio，并释放连接
  • 识别重复消息、HITL 超时、连接泄漏三类问题

初始化：一次 init，自动挂 Hook + Tracer

StudioManager.init() 是单例入口：建 HTTP / WebSocket 客户端、注册 run、连接 WebSocket； 成功后自动 AgentBase.addSystemHook(new StudioMessageHook(...))，并注册一个 TelemetryTracer StudioManager.java:214-260。 

StudioManager.init()
    .studioUrl("http://localhost:3000")
    .project("MyProject")
    .runName("experiment_001")
    .initialize()
    .block();

StudioConfig 默认 URL 是 http://localhost:3000，项目名 UnnamedProject，runName 是 run_<时间戳>，runId 是随机 UUID， 最大重试 3 次，WebSocket 重连 3 次，重连间隔 1 秒、上限 5 秒 StudioConfig.java:149-158。 文档示例里的 8000 只是示例端口，不是默认值。

不要再手动挂一次 Hook

文档第 2 步让你 .hook(new StudioMessageHook(...)) studio.md:37-42， 但 initialize 已经挂过 system hook；两条路径都生效时，同一条最终消息会被推两次。

消息：Hook 只推 PostCall 的最终消息

StudioMessageHook 只处理 PostCallEvent：取 getFinalMessage()， 调 StudioClient.pushMessage；失败只记日志，不让 Agent 调用失败 StudioMessageHook.java:66-95。 所以它不覆盖每条 token、每次工具调用或中间推理。

要看完整的工具与推理过程，用 trace / telemetry，而不是这个消息 Hook。文档说「每条 user / assistant / tool 消息都被同步」是过度概括 studio.md:48-52。

HITL：让真人扮演一个 Agent

StudioUserAgent 继承 AgentBase，通过 WebSocket 等 Studio 侧输入； 它调用 requestUserInput，把输入包装成 Msg 返回给调用方 StudioUserAgent.java:74-82 :120-186。 

StudioUserAgent reviewer = StudioUserAgent.builder()
    .name("Reviewer")
    .studioClient(StudioManager.getClient())
    .webSocketClient(StudioManager.getWebSocketClient())
    .inputTimeout(Duration.ofMinutes(10))   // 默认 30 分钟
    .build();

Msg answer = reviewer.call(inputMsg).block();

studioClient 与 webSocketClient 必须同时设置，否则 Studio 通道不完整； inputTimeout 默认 30 分钟 StudioUserAgent.java:244-327。

生产：用开关关掉，并释放连接

生产一般不在每次调用时向 Studio 写一份数据。用 Profile 或 @ConditionalOnProperty 控制初始化 studio.md:65-75； 关闭时调用 StudioManager.shutdown()，释放 WebSocket 与 OkHttp 连接。 

@Bean
@ConditionalOnProperty("agentscope.studio.enabled")
StudioMessageHook studioHook() {
    StudioManager.init().studioUrl(url).project(project).initialize().block();
    return new StudioMessageHook(StudioManager.getClient());
}

注意：如果 initialize 已经自动挂 Hook，这个 bean 只适合「手动接管」的场景；否则会重复。 最稳妥的做法是只调 initialize()，不额外注册 Hook。

验收：最终消息、trace、HITL 分开看

  1. 最终消息
    一次 agent.call() 后，Studio 只出现一条最终回复。
  2. trace
    工具调用与推理链路能在 trace / telemetry 里看到，而不是消息列表。
  3. HITL
    Studio 弹出输入框，StudioUserAgent.call() 暂停；提交后继续。
  4. 超时
    不输入时，达到 inputTimeout 后返回中断结果，不永久挂起。
  5. 关闭
    关闭开关后不再推送；shutdown 后进程能正常退出。

失败边界

现象更可能的原因处理
同一条消息出现两次initialize 自动 Hook + 手动 Hook去掉手动 .hook(...)
Studio 只有最终回复消息 Hook 只处理 PostCall工具/推理看 trace
HITL 一直等WebSocket 没连上 / 没配 client检查两个 client 与 Studio 服务
HITL 很快中断inputTimeout 太短显式设置更长的超时
进程退出卡住没 shutdown WebSocket / OkHttp停机钩子调 StudioManager.shutdown()
