36A-1 · Nacos A2A 端到端：注册、发现与验收

这一页只做一件事：把 A2A Agent 注册进 Nacos，并让另一个进程按名字发现它。 「注册成功」和「能被发现」是两件事；中间任何一段没接上，控制台都可能只显示一张孤立的 AgentCard。

读完你能做到

  • 说清 Nacos 里到底存了什么：AgentCard、Transport Endpoint，还是 Agent 实例
  • 用 NacosAgentRegistry + AgentScopeA2aServer 完成服务端注册
  • 用 NacosAgentCardResolver 在客户端按名字解析远端 Agent
  • 配好 agentscope-nacos-spring-boot-starter 的 A2A 前缀
  • 按「卡是否发布 → 端点是否可达 → resolver 是否命中」三段排查

边界：注册的是卡与端点，不是进程

Nacos A2A 子模块负责两段：服务端把 AgentCard 与服务端点写进 Nacos，客户端按名字解析出卡 nacos.md:26-53。 Nacos 不代理一次 A2A 调用，也不证明对端进程还活着；它只保存「这张卡 + 这些端点」。

NacosA2aRegistryProperties 是一个四字段 record：isSetAsLatest、 enabledRegisterEndpoint、overwritePreferredTransport、transportProperties NacosA2aRegistryProperties.java:34-38。 builder 默认 enabledRegisterEndpoint=true、setAsLatest=false、覆盖 transport 为 null NacosA2aRegistryProperties.java:83-92。 关掉 enabledRegisterEndpoint 就只发布卡，不发布端点。

服务端：NacosAgentRegistry + AgentScopeA2aServer

NacosAgentRegistry 是 A2A 服务端与 Nacos 之间的适配器。它的 builder 接受 AiService 或 Nacos Properties，nacosA2aProperties 可选；不传时用默认 properties NacosAgentRegistry.java:250-306。 

NacosAgentRegistry registry = NacosAgentRegistry.builder(nacosProperties)
    .nacosA2aProperties(NacosA2aRegistryProperties.builder()
        .enabledRegisterEndpoint(true)
        .build())
    .build();

然后把它交给 AgentScopeA2aServer。builder 必须传 ReActAgent.Builder 或 AgentRunner，注册方法叫 withAgentRegistry(...) AgentScopeA2aServer.java:174-184 :333。 

AgentScopeA2aServer server = AgentScopeA2aServer.builder(agentBuilder)
    .agentCard(agentCard)                 // ConfigurableAgentCard
    .withAgentRegistry(registry)
    .deploymentProperties(8080)
    .build();
文档写法会编译失败

官方页写 AgentScopeA2aServer.builder().agentRegistry(...) nacos.md:107-110。 实际没有无参 builder，方法也叫 withAgentRegistry。照抄会直接卡在编译期。

客户端：resolver 只认 Properties / AiService

NacosAgentCardResolver 只有 (Properties) 与 (AiService) 两个构造器； Agent 名不是构造参数，而是 A2aAgent.builder().name(...) 提供的 NacosAgentCardResolver.java:75-88。 

NacosAgentCardResolver resolver = new NacosAgentCardResolver(nacosProperties);

A2aAgent translator = A2aAgent.builder()
    .name("translator")
    .agentCardResolver(resolver)
    .build();

解析器内部有 agentCardCaches 与 agentCardUpdaters：第一次按名取时订阅， 后续命中缓存，Nacos 侧更新通过监听器回写 NacosAgentCardResolver.java:113-121。 所以改了卡不必重启 resolver，但你的 A2aAgent 什么时候重新读卡仍取决于它自己的调用时机。

Spring Boot：前缀与自动装配

agentscope-nacos-spring-boot-starter 使用两组前缀： agentscope.nacos.* 与 agentscope.a2a.nacos.* NacosConstants.java:29-38。 A2A 的父开关 agentscope.a2a.nacos.enabled 关闭时，注册 / 发现两个子开关都不会生效； 打开父开关后，再分别控制注册与发现。 

agentscope:
  nacos:
    server-addr: 127.0.0.1:8848
  a2a:
    nacos:
      enabled: true
      registry:
        enabled: true
      discovery:
        enabled: true

验收：三段都要过

  1. 卡发布
    Nacos 控制台能看到 AgentCard，名字与版本和代码一致。
  2. 端点可达
    Endpoint 的 URL 从调用方机器能直接访问；不要只在本机 curl localhost。
  3. resolver 命中
    另一个进程用 A2aAgent 按名字解析，拿到同一张卡，并能发出一次真实调用。

注册是显式动作，不是类加载时自动完成。新版本或新实例上线时，要重新调用注册流程；不要把「Nacos 里还留着旧卡」当成「新实例已经可用」。
