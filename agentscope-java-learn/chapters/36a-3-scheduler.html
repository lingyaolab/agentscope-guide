36A-3 · Scheduler：Quartz 与 XXL-Job 落地

Scheduler 的难点不是写 CRON，而是分清「谁持有调度状态」。Quartz 把 Trigger 放在 Java 进程 / Quartz 数据库； XXL-Job 只把 Agent 注册成 JobHandler，真正的 CRON 在 admin 控制台。选错模型，代码看起来一样，行为完全不同。

读完你能做到

  • 用 Quartz 跑通 CRON、固定速率与固定延迟，并正确 pause / resume
  • 知道 Quartz 的默认 NONE 为什么会让任务「注册成功但从不触发」
  • 用 XXL-Job 注册 JobHandler，并在控制台完成排程
  • 说清 XXL-Job 为什么不支持 cancel / pause，以及替代操作
  • 按「不触发 / 重复触发 / 停不下来」三类现象排查

Quartz：显式模式，显式启动

QuartzAgentScheduler.builder().build() 默认 autoStart=true、 schedulerId=default-scheduler，build 时启动 Quartz QuartzAgentScheduler.java:626-629 :671-689。 Job 统一放在 agentscope-quartz 组里，按 Agent 名做 JobKey :224-231。 

QuartzAgentScheduler scheduler = QuartzAgentScheduler.builder()
    .schedulerId("daily")
    .autoStart(true)
    .build();

ScheduleConfig cfg = ScheduleConfig.builder()
    .cron("0 0 8 * * ?")
    .zoneId("Asia/Shanghai")
    .build();

scheduler.schedule(agentConfig, cfg);
scheduler.pause("DailyReportAgent");
scheduler.resume("DailyReportAgent");

CRON / FIXED_RATE / FIXED_DELAY 分别映射为 CronTrigger、重复 SimpleTrigger、执行完再排下一次的固定延迟 QuartzAgentScheduler.java:246-305。 pause / resume 只在具体 QuartzAgentScheduler 类型上，不在 AgentScheduler 接口 AgentScheduler.java:77-190。

默认 schedule(agentConfig) 用 NONE，不会触发

便利方法内部是 ScheduleConfig.builder().build()，模式默认 NONE QuartzAgentScheduler.java:154-156。 在 Quartz 实现里 NONE 不会走进任何 scheduleJob 分支，但任务句柄仍会被放进 map 并返回 :272-315。 表面注册成功，实际永远不会跑。

XXL-Job：只注册 JobHandler

XxlJobAgentScheduler 不负责 Java 内排程，只把 Agent 名注册成 XXL-Job 的 JobHandler； CRON、并发、路由、日志都在控制台配置 scheduler.md:101-108。 因此它只接受 ScheduleMode.NONE，传其他模式会抛 UnsupportedOperationException XxlJobAgentScheduler.java:148-161。 

XxlJobSpringExecutor executor = new XxlJobSpringExecutor();
executor.setAdminAddresses("http://localhost:8080/xxl-job-admin");
executor.setAppname("agentscope-demo");
executor.setAccessToken("xxxxxxxx");
executor.start();

AgentScheduler scheduler = new XxlJobAgentScheduler(executor);
scheduler.schedule(agentConfig, ScheduleConfig.builder().build());

XXL-Job 实现不支持 cancel，调用即抛异常，提示去控制台暂停或删除 Job XxlJobAgentScheduler.java:289-304； 也没有 pause / resume :106-108。

XXL-Job 控制台：注册之后还要排程

  1. 确认执行器
    控制台「执行器管理」里能看到 appname，且地址在线。
  2. 确认 JobHandler
    新建任务时，JobHandler 填 Agent 名，例如 DailyReportAgent。
  3. 配置调度
    CRON、路由策略、阻塞处理、失败重试都在控制台；Java 侧不参与。
  4. 手动触发一次
    先「执行一次」看日志，再启用 CRON，避免表达式写错后等一天。

集群：Quartz 共享数据库，XXL-Job 靠 admin 路由

维度QuartzXXL-Job
调度状态在哪Quartz 数据库（集群时共享）XXL-Job admin
多副本共享 JobStore，靠 Quartz 集群锁admin 路由到某个执行器
控制台无内置，需自己接自带任务、日志、重试
暂停 / 取消代码内 pause / resume / cancel控制台操作

Quartz 集群需要共享的 Quartz 数据库；XXL-Job 则要确认执行器注册成功、admin 能回调到执行器。 两者都不是「多副本就自动只跑一次」，业务侧仍要准备幂等键。

运行时控制：谁能停、停到什么程度

ScheduleAgentTask 只有 cancel() 这类最小控制；Quartz 额外提供 pause / resume。暂停不冻结已经开始的外部进程，取消也不自动回滚已经产生的副作用。 真正需要「停止 + 回滚」时，幂等与补偿仍在业务侧。

验收：一次触发 + 一次暂停

  1. Quartz 触发
    用 FIXED_RATE 5 秒跑一次，日志至少出现两次执行。
  2. Quartz 暂停
    pause 后等一个周期不再触发；resume 后恢复。
  3. NONE 对照
    故意用默认 schedule(agentConfig)，确认任务从不触发。
  4. XXL-Job 注册
    控制台出现 JobHandler，手动执行一次成功。
  5. 控制台排程
    配置 CRON 后到点触发，日志能在控制台看到。

选型：先问谁持有状态

需求优先注意
本地 / 小集群、不想引入外部调度服务Quartz共享 Quartz 数据库；显式模式，别用 NONE
需要控制台、跨节点路由、任务日志XXL-JobJava 只注册；调度与停用都在控制台
要接别的调度框架自己实现 AgentScheduler接口没有 pause / resume，别照文档设计
