35 · 技能仓库：Git / MySQL / PostgreSQL

第 16 章讲技能本身：SKILL.md 怎么写、怎么加载、怎么变成工具。这一章讲「技能放在哪、怎么读、能不能改」。 AgentSkillRepository 只有一个很薄的仓库契约，但三种实现的边界完全不同： Git 是只读的版本化来源，MySQL / PostgreSQL 是可在线编辑的数据库；选错仓库，问题不在 Agent，而在内容运营流程。

读完你能做到

  • 说清 AgentSkillRepository 的读取、写入、删除与可写标志各自由谁实现
  • 解释 Git 仓库为什么是只读的，以及 autoSync 的 remote 检查与 pull 时机
  • 按 MySQL / PostgreSQL 的表结构理解技能、资源与 metadata_json 的兼容模式
  • 识别文档里 MySQL 构造器写错的地方，并用 builder 或三参构造器替代
  • 说清多仓库的优先级：后注册的仓库覆盖同名技能，失败仓库会被跳过
  • 按「版本审阅」还是「在线运营」选择 Git、MySQL、PostgreSQL 或 Nacos

技能仓库管的是「来源」，不是「技能内容」

AgentSkill 用 Markdown + 资源文件描述可复用技能；AgentSkillRepository 负责把这些技能从外部存储加载进来， 再交给 Toolkit / ReActAgent 使用 overview.md:6。 所以仓库层的核心问题不是「怎么让模型学会技能」，而是「技能从哪来、什么时候刷新、谁能改」。

仓库典型内容来源写入刷新方式
Git远程仓库里的技能目录只读读操作前检查 remote ref，变化才 pull
MySQL数据库两张表可写（可关）每次调用重新加载
PostgreSQLschema 下两张表可写（可关）每次调用重新加载
Nacos配置中心由 Nacos 管理由 Nacos 客户端刷新

契约：读取、写入、可写标志

AgentSkillRepository 继承 AutoCloseable，核心方法是按名取、列全部名称、取全部技能、保存、删除、判断存在， 再加仓库信息、来源标识与可写标志 AgentSkillRepository.java:35-132。 技能 ID 的格式是 name_version_source，这也是多仓库共存时区分同名技能的关键 AgentSkillRepository.java:46-53。

方法语义失败 / 边界
getSkill(name)按名取单个技能名字非法抛 IllegalArgumentException
getAllSkills() / getAllSkillNames()列出全部技能 / ID返回空列表而不是 null
save(skills, force)upsert；同名更新只读仓库返回 false，不抛错
delete(name)删除技能只读仓库返回 false
setWriteable / isWriteable控制是否允许写Git 永远 false；数据库可配置

加载：每次调用重建技能视图

ReActAgent.builder().skillRepository(repo) 可以注册一个或多个仓库；后注册的优先级更高， 同名技能由后者覆盖。至少注册一个仓库且动态技能开启时，build() 会挂上 DynamicSkillMiddleware，在每次 call() 前重建技能 prompt ReActAgent.java:5346-5354。 

ReActAgent agent = ReActAgent.builder()
    .name("assistant")
    .model(model)
    .skillRepository(repo)
    .build();

中间件按仓库顺序逐个 getAllSkills()，按技能名合并，后面的覆盖前面的；单个仓库加载失败只记日志并跳过， 不会让整个 Agent 启动失败 DynamicSkillMiddleware.java:165-192。 这也解释了数据库仓库「改完即生效」的说法：下一次 call() 会重新读表。

Git：版本化来源，只读

Git 仓库把一个远程仓库克隆到本地，HTTPS / SSH 都支持；默认使用临时目录，公开仓库可以直接用单参构造器 git-repository.md:6 git-repository.md:32-43。 技能目录的约定是：每个技能一个文件夹，里面放 SKILL.md；没有显式 skillsRoot 时， 先找仓库下的 skills/，没有就把仓库根当技能根 GitSkillRepository.java:220-227。 

GitSkillRepository repo = new GitSkillRepository(
    "https://github.com/agentscope/skills.git",
    "develop",
    Path.of("/var/skills/repo"),
    "agentscope-public",
    true);

Git 仓库是只读的：save / delete 只打警告并返回 false，isWriteable() 恒为 false GitSkillRepository.java:308-328。 要改技能，走 Git 提交与合并，而不是在 Java 侧调用 save。

Git 同步：先看 remote ref，再决定 pull

autoSync=true（默认）时，getSkill / getAllSkills / skillExists 等读操作前会先 ls-remote 查远端 HEAD；只有变化时才真正 pull git-repository.md:73-76 GitSkillRepository.java:711-738。 autoSync=false 时不会自动 pull，读之前必须自己调 sync()，否则会抛 IllegalStateException GitSkillRepository.java:530-538。

模式读操作前做什么适合
autoSync=truels-remote 比对远端 HEAD，变化才 pull希望技能随 Git 更新
autoSync=false不检查；必须显式 sync()启动时同步一次，或外部定时同步

临时目录会在 JVM 退出时自动删除，close() 也能提前清理；强制 kill 进程可能残留，需要外部清理 git-repository.md:84-88。 私有仓库复用系统 Git 配置：HTTPS 走 credential helper，SSH 走 ~/.ssh/ 与 agent git-repository.md:57-71。

MySQL：在线 CRUD，表结构固定

MySQL 仓库适合「管理后台在线编辑、Agent 立即读取」的流程。它用两张表：agentscope_skills 存技能本身， agentscope_skill_resources 存资源文件，资源表通过 id 外键级联删除 mysql-repository.md:46-74。 skill_content 存 SKILL.md 全文，metadata_json 存完整 metadata 树。

文档里的 MySQL 构造器在源码里不存在

文档快速上手写的是 new MysqlSkillRepository(ds, true) mysql-repository.md:36-37， 自定义表名又写成五参构造器 mysql-repository.md:83-90。 但 2.0.4 源码只有一个 public 构造器： (DataSource, boolean createIfNotExist, boolean writeable) MysqlSkillRepository.java:174-183。 自定义库名 / 表名请用 builder(ds) MysqlSkillRepository.java:1199-1217。 照文档两参 / 五参写法会直接编译失败。 

MysqlSkillRepository repo = MysqlSkillRepository.builder(dataSource)
    .databaseName("skill_center")
    .skillsTableName("ops_skills")
    .resourcesTableName("ops_skill_resources")
    .createIfNotExist(true)
    .writeable(true)
    .build();

builder 默认库名 agentscope、表名 agentscope_skills / agentscope_skill_resources， createIfNotExist 与 writeable 都默认 true MysqlSkillRepository.java:1210-1217。 保存与删除都在事务里执行，资源表 ON DELETE CASCADE 防止孤儿资源 mysql-repository.md:93-109。

PostgreSQL：schema 隔离，同一套 CRUD

PostgreSQL 仓库与 MySQL 版结构几乎一样，差异在命名空间：它用 schema 而不是 database 隔离， 数据库由 JDBC URL 决定；默认 schema agentscope，默认表名与 MySQL 相同 postgresql-repository.md:51-86 PostgresSkillRepository.java:128-134。 

PostgresSkillRepository repo = PostgresSkillRepository.builder(dataSource)
    .schemaName("my_schema")
    .skillsTableName("my_skills")
    .resourcesTableName("my_resources")
    .createIfNotExist(true)
    .writeable(true)
    .build();

builder 默认 schemaName=agentscope、createIfNotExist=true、writeable=true PostgresSkillRepository.java:1299-1306。 createIfNotExist=true 会先建 schema，再建两张表；已有表不会自动加 metadata_json postgresql-repository.md:83-86。

metadata_json：完整模式与兼容模式

新表会带 metadata_json，用来保存完整 metadata 树；已有表如果没有这一列，仓库不会自动 ALTER TABLE，而是降级成「只往返 name + description」的兼容模式 MysqlSkillRepository.java:78-83 MysqlSkillRepository.java:415-435。 PostgreSQL 行为一致。

兼容模式不是「无损」

没有 metadata_json 时，技能仍能加载，但 version / homepage / license 等扩展 metadata 可能丢失。 需要完整往返时，自己执行文档给出的 ALTER TABLE ... ADD COLUMN metadata_json ...，再重启仓库。

writeable：连接级开关，不是权限系统

数据库仓库的 writeable 是进程内开关：为 false 时 save / delete 直接返回 false， 不会改库；setWriteable(true/false) 可以运行时切换 MysqlSkillRepository.java:600-609 MysqlSkillRepository.java:903-909。 它不能替代数据库账号权限：真正只读的服务仍应使用只读数据库用户。

多仓库：后注册的覆盖同名技能

一个 Agent 可以注册多个仓库，顺序从低优先级到高优先级；同名技能由后面的仓库覆盖 ReActAgent.java:5346-5354。 这适合「基础技能集 + 团队覆盖层」：Git 放通用技能，数据库放少量团队定制。 

ReActAgent agent = ReActAgent.builder()
    .name("assistant")
    .model(model)
    .skillRepositories(List.of(gitRepo, mysqlRepo)) // mysqlRepo 优先
    .build();

加载失败不会中断整个 Agent：中间件会记录哪个仓库失败、继续用其余仓库 DynamicSkillMiddleware.java:169-183。 但「少了一个仓库」不一定报错，所以生产上要监控加载日志，而不是只看 Agent 能否回复。

运维：凭据、临时目录与连接池

Git 凭据。Java 侧不管账号密码，HTTPS 用系统 Git credential helper，SSH 用 ~/.ssh/ 与 agent； CI runner 要提前准备好这些配置 git-repository.md:57-71。

临时目录。默认克隆到临时目录，JVM 退出或 close() 时清理；多实例各自一份 clone，没有锁竞争 git-repository.md:84-88。 强制 kill 可能残留，磁盘告警时要检查临时目录。

数据库。用 HikariCP / PgBouncer 等连接池；createIfNotExist=true 会执行 DDL，生产要确认账号有建库 / 建表权限， 或者预先建好 schema 再用 false。

故障边界：先分清读不到、写不进、刷新不了

症状更可能的原因先查什么
Git 加载失败URL / 分支错、凭据不可用、临时目录不可写手动 git ls-remote、SSH agent、临时目录权限
Git 一直不更新autoSync=false 且没调 sync()同步策略与 sync() 调用
数据库 save 返回 falsewriteable=false，或 Git 仓库只读isWriteable()
MySQL 代码编译失败照文档用了不存在的构造器改用三参构造器或 builder
技能 metadata 丢失旧表没有 metadata_json表结构 / 兼容模式
同名技能被覆盖多仓库优先级：后者胜出仓库注册顺序与 source
Agent 少了一个技能某个仓库加载失败被跳过中间件日志中的「failed to load」

六个坑：把仓库当文件系统

坑一：对 Git 仓库调 save。它只读，save 只打警告并返回 false，不会提交任何东西 GitSkillRepository.java:308-328。

坑二：关掉 autoSync 却不调 sync。读操作会直接抛「Repository is not synchronized」 GitSkillRepository.java:530-538。

坑三：照文档写 MySQL 二参构造器。源码没有这个重载；用三参构造器或 builder mysql-repository.md:36-37 MysqlSkillRepository.java:174-183。

坑四：以为旧表自动加 metadata_json。不会；旧表会降级到只往返 name + description MysqlSkillRepository.java:78-83。

坑五：以为 writeable=false 是权限系统。它只是进程内开关；数据库账号仍应使用只读用户。

坑六：同名技能被覆盖却不自知。多仓库按注册顺序合并，后者覆盖前者；用 source / 日志确认最终生效的是哪一个 DynamicSkillMiddleware.java:169-192。

自测：三个判断题

Git 技能仓库可以直接 save 新技能吗？

不能。它只读，save / delete 只打警告并返回 false；要改技能走 Git 提交 GitSkillRepository.java:308-328。

new MysqlSkillRepository(ds, true) 在 2.0.4 里能编译吗？

不能。公开构造器只有三参版本；自定义库名 / 表名用 builder(ds) MysqlSkillRepository.java:174-183。

多个仓库有同名技能时，谁生效？

后注册的仓库优先；中间件按仓库顺序加载，后面的覆盖前面的同名技能 ReActAgent.java:5346-5354。

练习：给技能选一条来源与刷新策略

目标不是把技能读出来，而是能解释「谁能改、什么时候变、冲突谁赢」。建议 45 分钟：

  1. 列技能来源
    把一个通用技能与一个团队技能分别归到 Git 与数据库，写下理由。
  2. 跑 Git 仓库
    用默认 autoSync 读一次，改远端后读第二次，确认 ls-remote + pull 生效。
  3. 试只读
    对 Git 仓库调 save，确认返回 false 且没有提交。
  4. 建 MySQL 仓库
    用 builder 建库建表，保存一个带资源文件的技能，检查两张表与级联删除。
  5. 验证 metadata
    检查 metadata_json；再模拟旧表没有该列，观察兼容模式。
  6. 分层覆盖
    Git 与数据库放同名技能，注册顺序不同，确认后者覆盖前者。
  7. 关一次写入
    把 writeable 设为 false，调 save / delete，确认返回 false 且库不变。
  8. 写三行结论
    分别写「技能从哪来」「何时刷新」「同名谁赢」，确保每行都能在日志或表里找到证据。
