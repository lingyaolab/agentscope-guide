36A-5 · Training：影子流量、奖励与 commit

Training 不是「把生产模型换掉」，而是把命中采样的请求复制一份，在异步线程池里用 Trinity 模型再跑一遍， 算奖励、回 feedback，再周期 commit。这一页把采样、标记、奖励、提交四段拆开，并给出最小验收。

读完你能做到

  • 说清生产调用与影子调用的关系，不再把 Training 当模型替换
  • 在按比例采样与显式标记之间选择
  • 实现一个可解释的 RewardCalculator
  • 设置 commit 周期，并知道 stop() 会做最后一次提交
  • 按「没有样本 / 没有奖励 / 没提交」三类现象排查

影子流量：生产响应不等影子

TrainingRunner.start() 把 TrainingRouter 注册成全局 system hook TrainingRunner.java:115-133。 命中采样后，路由器不会改动生产调用，而是克隆 Agent、把模型换成 TrinityModelAdapter， 在异步线程池里再跑一遍 TrainingRouter.java:221-249 :277-298。

所以「采样命中」只意味着多跑一次影子，不意味着用户看到 Trinity 的结果。影子 Agent 的名字里带 -shadow 时会被跳过，避免递归训练。

采样：按比例还是显式标记

策略行为适合
SamplingRateStrategy.of(0.1)按比例随机采样，10% 流量进训练普通在线流量
ExplicitMarkingStrategy.create()只训练带 TrainingContext.mark 的调用人工挑高质量样本
自定义 TrainingSelectionStrategy按业务规则决定按租户 / 工具 / 评分筛选

不传策略时默认 10% 采样 TrainingConfig.java:251-254。 ExplicitMarkingStrategy.create() 的标记 TTL 是 1 分钟 ExplicitMarkingStrategy.java:58-70。

显式标记：通过 Reactor Context 传播

agent.call(msg)
    .contextWrite(TrainingContext.mark("prod", "high-quality"))
    .block();

TrainingContext.mark(...) 返回一个 Reactor Context 写入函数，必须通过 .contextWrite(...) 使用；标记会跨线程传播 TrainingContext.java:81-137。 如果标记写在 call() 之后或没有进入响应式链，策略会当作「未标记」拒绝。

奖励：实现 RewardCalculator，不是 Function

rewardCalculator 的实际类型是 RewardCalculator，方法是 double calculate(Agent agent)；Lambda 能写，是因为它是函数式接口 RewardCalculator.java:26-34。 

TrainingRunner runner = TrainingRunner.builder()
    .trinityEndpoint("http://localhost:8080")
    .modelName("/path/to/model")
    .selectionStrategy(ExplicitMarkingStrategy.create())
    .rewardCalculator(new RewardCalculator() {
        @Override
        public double calculate(Agent agent) {
            return scoreByToolCallsAndLength(agent);
        }
    })
    .commitIntervalSeconds(300)
    .build();

奖励值通常落在 -1 到 1；不要只按回答长度打分，否则训练会奖励啰嗦。工具调用次数、任务是否完成、人工评分都可以进公式。

commit：默认 300 秒，stop 再提交一次

commitIntervalSeconds 默认 300；<= 0 会关闭定时 commit TrainingConfig.java:125-137 TrainingRunner.java:185-214。 stop() 不是简单关线程：先关 commit 调度器，再做一次最终 commit()， 最后移除 TrainingRouter :139-168。

进程被强制 kill 时，最后一次 commit 不会发生；对训练数据完整性要求高时，优雅停机比刷日志更重要。 也可以显式调 runner.commit().block() 做手动提交（commit() 返回惰性的 Mono）。

验收：只训练该训练的样本

  1. 策略
    不标记的调用不产生样本；标记的调用产生一条。
  2. 影子
    生产响应不等待影子完成；日志能看到 shadow Agent 执行。
  3. 奖励
    反馈日志出现 reward 值，且不是固定常数（除非你故意用常数）。
  4. commit
    周期到达时出现 commit 成功；stop 后还有最后一次提交。
  5. 递归
    影子 Agent 不再触发训练；名字含 -shadow 的会被跳过。

失败边界

现象更可能的原因处理
完全没有样本采样未命中 / 未标记换 Explicit 策略并检查 contextWrite
有样本没奖励RewardCalculator 抛错 / 返回常数看日志与实现
一直不 commitinterval <= 0 / 线程被阻塞检查配置与 commit 日志
影子拖慢生产误以为同步执行它应异步；检查线程池与阻塞点
训练递归自定义 cloner 或手工改写影子 Agent 名，未保留 -shadow使用默认 cloner，或确保名字含 -shadow
